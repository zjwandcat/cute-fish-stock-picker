# 月度算法核验与运行边界

## 2026-09-17 Windows 11 实测

环境：Windows 11 10.0.26340，Python 3.14，NVIDIA GTX 1650 Max-Q。
真实数据来自本机 10q 项目，数据库为 `output/21BB/p2/21BB_p2_study.db`。
Trial 157 必须唯一且 COMPLETE，固定参数从同目录配置读取；缺失即失败。

| 环节 | 实际执行 |
| --- | --- |
| M0 | 自动检查当前月份所需连续窗口，缺失月份联网补数并调用原 pipeline、FactorCalculator、stock_filter 与 scheme_b 中性化 |
| M1 | 原项目 LabelMaker 与 RollingSplitter；58 月训练、12 月验证、1 月预测；月份缺口、重复股票、文件日期错误会拒绝 |
| M2 | 原项目 FeatureStore、EnsemblePredictor、PortfolioBuilder；114 个保留因子；5 只 13% + 5 只 7% |
| M3 | 原项目 TETEngine，单月新建仓状态；输入原 M0 因子，输出实际调整比例；失败不再跳过 |
| M4 | 原项目 Barra 暴露 + 双模型原生 TreeSHAP；十只股票的贡献加和须还原模型得分 |

M0 的中性化由上游 `neutralization.py::neutralize_scheme_b` 执行 MAD、Rank-Z、行业/市值 OLS，已有因子不重复中性化。已有历史因子库仍按用户提供的 10q 数据信任并记录指纹；新增月份由平台自动调用同一算法生成。

下列为自动补数修复前、202601 窗口的历史实测，不能代表首次下载耗时：CPU 单次 19.784 秒；自动 CUDA 单次 16.879 秒；命中磁盘缓存的进程总耗时 1.747 秒。不同设备/运行波动下不可承诺相同加速比。CPU 与 CUDA 当时十只股票完全相同。贡献加和最大误差 CPU 为 6.49e-8。

名单：白云机场、深天马 A、海信家电、嘉化能源、九洲药业、东睦股份、大华股份、颀中科技、华测检测、长江传媒。

自动更新目标按 Asia/Shanghai 当前月份确定。202609 必须使用 202010–202608 共 71 个连续 M0 月份；缺少任一月份、训练标签覆盖不足 90% 或执行失败都不能返回旧持仓。202608 的未来收益标签保持 NaN，不取尚未结束的 202609 价格。

新增 M0 使用交易日历计算上市天数、近 20 交易日日均换手率、当月实际缺失交易天数，送入原 `stock_filter.py`。普通财报接口按股票缓存，再按公告日期与报表截止日筛选；实际公告日期晚于月末的修订不可进入历史月份。批量 VIP 财报接口不是运行前提。日线按交易日批量下载，财报在不同月份之间复用，统一限流并进行有界重试。

原上游历史日线的换手率因子仍沿用月末换手率广播的实现；ST 名称和行业沿用数据源当前股票基础表，历史名称/行业的严格时点回放不在本次补数范围内。宏观指标沿用上游 Tushare 实现，缺失保留 NaN，不在补数时启动 AKShare 的不定时长备用下载。

## 202609 自动补数实测

2026-09-17 已通过平台自动下载并生成 202601–202608 的 M0，连同已有历史数据组成 202010–202608 的 71 月窗口。20260831 预测池 1,275 只，所有股票均通过原筛选规则，预测月未来收益保持 NaN。实际执行窗口为训练 202010–202507、验证 202508–202607、预测 202608，最终报告月份为 202609。

纯 CPU 单窗口耗时 22.977 秒（不含首次补数）；模型贡献加和最大误差 2.19e-8。高比例组为心脉医疗、当升科技、视源股份、先导智能、青岛双星，各 13%；低比例组为璞泰来、特锐德、利亚德、中伟新材、金力永磁，各 7%。本次 M3 均为 HOLD；长鑫科技不在预测池及十股结果中。

首次普通财报下载需要逐股票请求，完整补数属于分钟级以上任务，不应与单窗口训练耗时混淆。上市交易日计数经 5,903 条真实基础记录比对，批量版与原逐股票版完全一致，本机耗时由 15.374 秒降为 0.013 秒。后续仅补缺失月份，已有原始下载和完整 M0 直接复用。

验证包括月份窗口、财报公告时点、跨月复权标签补齐、损坏文件恢复、互斥锁、后台任务共享、旧结果拒绝，以及真实 71 月文件与最终十股检查。浏览器已确认 202609 列表和专业归因可用。真实结果和核验记录保存在本机 `.test-output/current-month-verification.json`，不提交原始数据。

## 保留上游语义的限制

- 不进行历史回测；训练仍需要历史样本，不能仅用一个月数据重新训练 Trial 157。
- M3 是有状态算法。本功能定义为单月新建仓，不等同于连续历史持仓的锚定趋势、卖出后重入状态。
- 上游 XGBoost `predict` 使用 `iteration_range=(0, best_iteration_)`，零值会使用所有已训练树；本次 `best_iteration_=0`。本桥接保持这一行为，归因使用同一树范围，没有擅自改成另一套 Trial 结果。
- 上游 XGBoost 虽读取 `lr_mode/decay_every/decay_factor`，当前 `fit` 没有把学习率衰减回调传入 `xgb.train`。不能宣称该部分参数已生效。要改变它需重验证原 Trial，不在性能优化时静默更改。
- M4 的已实现收益归因需要未来真实收益。当前只报告预测得分贡献与 Barra 风格暴露，不把缺失未来收益填成零后宣称归因成功。
- CUDA 仅用于 XGBoost；LightGBM 保持 CPU。用真实小模型及模型配置确认 CUDA，训练失败重试 CPU。

## 缓存与可重复性

缓存键包括 Trial 参数、依赖版本、Python/架构、设备模式、桥接和上游代码/配置内容、当前所需 M0 文件大小及纳秒修改时间。API `refresh=1` 可强制重算。新增 M0 先在临时目录生成并验证，再原子替换正式文件；跨进程文件锁避免重复下载。已完成月份和原始下载缓存支持断点续跑。

API 立即返回 `updating` 与阶段进度，后台单任务计算。当前月成功结果每小时重新检查输入，错误一分钟后可重试。应用启动、Token 保存和跨月时自动检查；程序关闭期间不运行。Python 最长 3 小时超时，保留已完成数据。浏览器、Node 与 Python 三层拒绝过期持仓。

原有归因采用因子值乘全局重要性，且 Booster 对象不一定提供 sklearn 风格的属性，可能退化成均匀权重，现已移除。新归因只对十只最终股票计算，保留基准项、前十二项、其余贡献与加和校验，避免全市场 SHAP 的开销。
